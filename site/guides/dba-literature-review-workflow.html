Guide · Research process

A reproducible literature review workflow for doctoral students

A literature review is judged on the argument, but it is defended on the audit trail. This seven-stage workflow is designed so that any search, exclusion or coding decision can be reconstructed months later, when a supervisor or examiner asks why a particular study is missing.

Why reproducibility matters more than volume

Doctoral candidates often respond to uncertainty by reading more. Reading more is rarely the problem. The failure mode is losing the ability to explain how the corpus was assembled: which database, which exact string, which date, which inclusion rule, and why the 2008 paper was excluded while the 2009 paper was kept. In a DBA or other professional doctorate, where the review usually supports an applied research question, an examiner is entitled to ask whether the search was systematic enough to support the claims being made. A clean, boring audit trail answers that question better than an impressive reading list.

The workflow below borrows the discipline of a systematic review without requiring you to register a protocol or produce a PRISMA diagram, unless your institution asks for one. It works in a spreadsheet plus a reference manager, with no specialist software.

Stage 1: write the question before the search string

Write one sentence stating the construct, the population or context, and the relationship of interest. Then list the synonyms for each concept. Search strings are built from those synonym lists, not from intuition on the day. For a study of dynamic capabilities and financial performance in Chinese firms, the concept buckets might be dynamic capabilities / absorptive capacity / organisational agility, financial performance / firm performance / ROA / Tobin's Q, and China / Chinese firms / emerging markets.

Save the question and the synonym list in a file called review-protocol.md inside your project folder. Date it. That single file is what turns a pile of PDFs into a defensible method.

Stage 2: log every search exactly as run

Create a search log with one row per query: date, database, the full string copied verbatim, field restrictions, date limits, language limits, and the number of hits. Copy-paste the string; do not paraphrase it. Databases change their syntax and their coverage, and "a search of Web of Science" is not a method — "TITLE-ABS-KEY(...) AND ... run on 2026-03-14, restricted to 2010-2026, 1,284 records" is.

Stage 3: deduplicate once, and record the count

Export to BibTeX or RIS rather than retyping. Deduplicate in your reference manager, note how many records were removed, and keep the raw exports untouched in a /raw folder. Never edit the raw export. If a later stage reveals a bad merge, you need the original file to recover it.

Stage 4: screen in two passes with a written rule

First pass: title and abstract against inclusion and exclusion criteria written before you start. Second pass: full text. Keep a screening log with one row per record and a reason code for every exclusion. Reason codes should be short and consistent — E1 wrong construct, E2 wrong context, E3 not empirical, E4 inaccessible full text. Free-text explanations feel more thorough but are impossible to summarise in a methods chapter.

Record borderline decisions separately rather than silently resolving them. If you are working with a supervisor, this is the list to bring to a meeting, and it is far more productive than asking "am I reading the right things?".

Stage 5: build a synthesis matrix, not an annotated bibliography

An annotated bibliography is a list of summaries arranged by author. A synthesis matrix is a table arranged by concept, which is what a literature review chapter actually needs. Columns typically include: citation, theoretical lens, construct definition, sample and context, method, key finding, measured outcome, limitations, and how it relates to your research question. One row per study; one column per concept you will write about.

The payoff is structural. When every study's definition of the central construct sits in a single column, the inconsistencies in the literature become visible as a pattern rather than as twelve disconnected paragraphs. That pattern is usually the contribution of your review: not "researchers have studied X", but "researchers mean three different things by X, and the empirical results divide along those definitions".

Stage 6: version everything

Keep the protocol, search log, screening log, synthesis matrix and manuscript in one folder under version control, or at minimum in dated snapshots. Use predictable names: 2026-03-14_screening-log_v3.csv. When a supervisor asks you to widen the date range in month eight, you can rerun Stage 2, quantify exactly how many new records entered, and update the methods paragraph with real numbers instead of reconstructing the whole process from memory.

Stage 7: make the methods paragraph write itself

If the first six stages are logged, the methods section is a transcription: databases searched, date of last search, exact strings or their location in an appendix, inclusion and exclusion criteria, number of records at each stage, and the coding scheme used in the matrix. Attach the search log as an appendix. This is also where you disclose limitations honestly — a single database, an English-only restriction, or a context restricted to one country.

Common failure modes

  • Search strings that drift. A slightly different string in week six produces a corpus nobody can reproduce. Always append to the log rather than silently substituting.
  • Reference-manager fields used as a database. Notes and tags are convenient but hard to export and harder to audit. Keep the structured data in a plain CSV or spreadsheet.
  • No exclusion reasons. "Not relevant" is not a reason; it is a missing record.
  • Citation formatting left to the end. Reformatting 200 references the week before submission is where silent errors enter. Run a format audit early and again at the end.
  • AI summaries without the source PDF. A generated summary is not evidence. Every coded cell in the matrix should trace back to a page number in a PDF you have opened.

Once the corpus is fixed, the mechanical work begins: check the reference list with the reference list auditor and read the APA 7 reference list guide for the formatting rules behind each flag.
